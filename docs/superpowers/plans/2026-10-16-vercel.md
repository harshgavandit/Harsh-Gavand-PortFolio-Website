# Vercel Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the complete portfolio and assistant from Vercel at harshgavand.dev without Render.

**Architecture:** Share the existing Node request handler between local HTTP serving and a Vercel API entry point. Use existing Redis persistence for global spending, shared admission and durable retry work, with a bounded request drain and an authenticated daily cron.

**Tech Stack:** React/TypeScript, Vite, Node 24, Vercel Functions/Cron, Upstash REST/Lua.

**Spec:** `docs/superpowers/specs/2026-10-16-vercel-design.md`

## Global Constraints

- Preserve genuine content, response contracts, the existing quota namespace and limits.
- No browser automation, no new provider key, no real provider call for migration verification.
- Do not publish credentials; use placeholders in deployment documentation.
- Keep Node 24 and all existing lint, type, build and pre-render gates.
- Work in the existing checkout under the user's ongoing direct implementation/push authorization; no routine worktree or design approval pause.
