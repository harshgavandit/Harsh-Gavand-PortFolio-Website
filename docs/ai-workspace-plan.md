## Streaming recruiter agent

- **Read.** POST /api/ai/agent accepts JSON with a role description between 12 and 6,000 characters. The server checks origin, content type, body size, admission, and shared rate limits. It redacts common identifiers and obvious instruction overrides before calling the provider. The first strict schema asks for three to eight verbatim requirements with a unique ID, category, and up to three search queries. The server validates the response before searching.
- **Search.** Deterministic project ranking, code retrieval, and experience matching supply at most 12 deduplicated sources. Each source has a stable ID. Links point to a canonical case study, the experience section, or a pinned GitHub file and line range.
- **Assess.** The second strict schema asks for a verdict and reason per requirement, a summary, and an intro email. Evidence IDs are limited by a request-specific enum. The server discards unknown or unrelated IDs, checks requested skills and duration against accepted sources, and resolves every link. A code excerpt can supplement an experience or project record. A technology name in a policy or test cannot establish experience on its own. The displayed prose is composed from the checked verdicts and published source labels.
- **Draft.** The result includes a copyable email. It references validated matches using public names and falls back to a neutral introduction when evidence is limited. The browser receives newline-delimited progress, result, or safe error events. Once a stream starts, errors are sent inside it. Preflight validation and admission errors retain their HTTP statuses.

Both model calls use separate reservations through the existing quota lifecycle. They use the configured model, no provider tools, no storage, and at most 1,000 output tokens each. The shared abort signal covers the request and stops the pipeline from starting a later stage after cancellation. An unknown provider outcome retains its reservation for accounting. The Node and Vercel handlers share the same implementation. The evaluator reserves two ledger slots before an agent request and keeps the isolated $0.10 cap. Four synthetic role cases add 16 model attempts across two repetitions. Offline tests use injected providers and quota stores.
