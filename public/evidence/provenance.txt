BANKING AGENT HARNESS
banking-harness.json records actual calls to the unchanged local banking tools and
services at 2b8b094bc80bef18f75b1e50c5235c77d5a246c9. The reproduction loader bypasses
ADK/provider startup and .env loading, provides a lightweight ToolContext fixture,
and sets the approval lifetime to the code default (24 hours). The executor outcome
is explicitly set to the project's mock SUCCESS mode. Policy, mock accounts, pending
state, limits, audit, transfer tools, and executor functions are the source modules.

Executed assertions:
- Valid proposal leaves mock balance at 200000 before confirmation.
- Later explicit confirmation succeeds and changes mock balance to 199000.
- Repeat confirmation returns NO_PENDING_TRANSFER.
- Blocked beneficiary is rejected with mock balance unchanged at 200000.
- Same invocation cannot confirm its own proposal.
- A separate session with separate state has no pending transfer to approve.

Names and account suffixes in the transcript come from the project's existing mock
fixtures. They are synthetic. The sample proves these deterministic function paths;
it does not prove a model conversation, live banking, ADK browser operation, Redis
integration, durable state, or production concurrency.
